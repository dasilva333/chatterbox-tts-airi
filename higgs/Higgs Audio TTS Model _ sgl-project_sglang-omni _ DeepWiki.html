Higgs Audio v3 TTS is a chat-native text-to-speech model built on a Qwen3-4B backbone. It generates 24 kHz speech using 8 discrete codebooks and supports voice cloning, multilingual synthesis, and fine-grained inline control tokens docs/cookbook/higgs_tts.md3-13

Pipeline Architecture

The Higgs TTS pipeline is a four-stage sequence that transforms text input into streaming audio waveforms.

Stage Responsibilities

  1. Preprocessing: Handles text tokenization and reference audio file I/O. It builds the full prompt and applies the delay pattern to reference codes sglang_omni/models/higgs_tts/stages.py8-11
  2. Audio Encoder: Runs the HiggsAudioCodec (a discrete tokenizer) to convert raw reference audio into multi-codebook tokens. This stage is a no-op if pre-encoded codes are provided sglang_omni/models/higgs_tts/stages.py12-13
  3. TTS Engine: Executes the HiggsTTSModel using an OmniScheduler. It manages the autoregressive (AR) generation of discrete tokens across 8 codebooks sglang_omni/models/higgs_tts/stages.py14-17
  4. Vocoder: A streaming scheduler that converts generated discrete tokens back into audio waveforms using the Higgs decoder sglang_omni/models/higgs_tts/stages.py18-19

Sources: sglang_omni/models/higgs_tts/stages.py1-20 docs/cookbook/higgs_tts.md41-47

Multi-Codebook Architecture

Higgs utilizes a multi-codebook discrete token representation. Audio is encoded into 8 codebooks at 25 FPS, which are then interleaved with text tokens in the backbone docs/cookbook/higgs_tts.md19-26

Delay Pattern and Sampler

The model uses a delay pattern where codebooks are staggered. The HiggsBatchedSamplerState manages the state machine for this pattern across multiple requests, tracking delay_count and eoc_countdown (End of Code) sglang_omni/models/higgs_tts/sampler.py40-54

Sources: sglang_omni/models/higgs_tts/sampler.py40-79 sglang_omni/models/higgs_tts/model.py73-90 docs/cookbook/higgs_tts.md19-26

Model Implementation Details

HiggsTTSModel

The HiggsTTSModel is a composition over sglang.srt.models.qwen3.Qwen3ForCausalLM sglang_omni/models/higgs_tts/model.py73-78 It adds specialized components for discrete audio:

  • HiggsFusedMultiTextEmbedding: A fused single-tensor embedding of shape [N*V, D] where $N$ is the number of codebooks and $V$ is the codebook vocab size sglang_omni/models/higgs_tts/model.py80-82
  • HiggsFusedMultiTextHead: A fused head tied to the embedding weights sglang_omni/models/higgs_tts/model.py82-83

HiggsTTSModelRunner and CUDA Graphs

To achieve low latency, the HiggsTTSModelRunner enables CUDA Graphs by default tests/unit_test/higgs_tts/test_pipeline.py30-110

  • Shadow Buffers: The runner uses _cg_active_* shadow buffers to gather sampler state before forward passes, avoiding illegal gather/scatter operations during graph capture sglang_omni/models/higgs_tts/model_runner.py2-9
  • Async Decode: It implements post_decode_launch for non-blocking D2H transfers of token snapshots into pinned host buffers sglang_omni/models/higgs_tts/model_runner.py69-85

Sources: sglang_omni/models/higgs_tts/model.py73-150 sglang_omni/models/higgs_tts/model_runner.py1-110

Audio Processing and Vocoder

HiggsAudioCodec

The codec weights are bundled within the TTS checkpoint under the prefix tied.embedding.modality_embeddings.0.model.* sglang_omni/models/higgs_tts/audio_codec.py31-32 The HiggsAudioCodec class extracts these directly from model.safetensors sglang_omni/models/higgs_tts/audio_codec.py73-101

Streaming Vocoder

The HiggsStreamingVocoderScheduler preserves batched non-streaming decode while emitting incremental audio chunks for streaming requests sglang_omni/models/higgs_tts/stages.py18-19

  • Streaming Metadata: Requests with stream: true trigger the construction of stream_metadata containing the codec contract (codebooks and vocab size) sglang_omni/models/higgs_tts/request_builders.py112-135
  • Payload Format: Audio is emitted as audio_waveform payloads containing raw bytes and shape information sglang_omni/utils/audio_payload.py12-36

Reference Audio Caching

Higgs implements a sophisticated caching mechanism for reference audio to avoid redundant encoding.

  • Memoization: The system uses _REF_PATH_HASH_MEMO to store file hashes keyed by file metadata (size, mtime, ctime) sglang_omni/models/higgs_tts/stages.py76-93
  • Sentinel Checks: To prevent stale hits on same-size file replacements, it reads "sentinel" chunks from the head, middle, and tail of the file sglang_omni/models/higgs_tts/stages.py96-108
  • Radix Cache Isolation: Requests are namespaced in the radix cache using an extra_key derived from the reference audio tokens, ensuring prompts with different speakers never share KV cache subtrees sglang_omni/models/higgs_tts/request_builders.py42-59
